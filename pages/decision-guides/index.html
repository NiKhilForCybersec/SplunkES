🚨 MANDATORY: Document Decision Rationale

Every architectural decision must be documented in the project scope. These guides help you choose, but the rationale must be captured for future reference. Undocumented decisions lead to technical debt and audit failures.

⚠️ Decision Reversibility

Some decisions are harder to reverse than others:

  • Easy to change: Sourcetype names, index routing, TA selection
  • Moderate effort: Ingestion method, Heavy Forwarder vs HEC
  • Difficult to change: Index structure, data model mappings, timestamp extraction

Consider long-term impact before committing to difficult-to-reverse decisions.

🧭 When to Use These Guides

Use these decision trees when you need to choose between competing approaches. Each guide walks through the decision systematically based on real-world constraints.

Example: Ingestion Method Selection

Sample ADR: Akamai WAF Ingestion 
## Decision: Akamai WAF via SIEM Integration

**Date:** 2024-01-15
**Decision Maker:** Detection Engineering Team
**Status:** Accepted

### Context
Need to ingest Akamai WAF logs for DDoS and web attack detection.
Options: SIEM Integration (HEC), Log Delivery Service (S3), Datastream.

### Decision
Use SIEM Integration with HEC push to Splunk Cloud.

### Rationale
- Considered alternatives: Log Delivery (S3 polling), Datastream
- Key factors: 
  - SIEM Integration is lowest latency (~2-5 min)
  - No additional infrastructure required
  - Akamai manages the integration
  - Directly supported by Akamai TA for Splunk

### Consequences
- **Positive:** Simple setup, low maintenance, good latency
- **Negative:** Dependent on Akamai-side configuration
- **Risks:** HEC token compromise could allow data injection

### Reversal Plan
Could switch to Log Delivery if SIEM Integration has issues.
Effort: Moderate (2-3 days to reconfigure)
