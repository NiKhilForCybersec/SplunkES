🚨 CRITICAL: HEC Token Security

HEC tokens are API keys that grant write access to Splunk. A compromised token can be used to inject malicious data or exhaust license. Follow these rules:

  • NEVER commit tokens to source control (Git, etc.)
  • ALWAYS use secrets managers (AWS Secrets Manager, Azure Key Vault, HashiCorp Vault)
  • ALWAYS restrict tokens to specific indexes (never allow "all indexes")
  • ROTATE tokens quarterly and immediately after any suspected compromise
⚠️ Splunk Cloud Token Management

In Splunk Cloud, HEC token creation requires coordination:

  • Token creation: May require Splunk Cloud support ticket (depending on stack config)
  • Lead time: Allow 1-3 business days for new token requests
  • Index permissions: Tokens can only access indexes that exist in cloud

Overview

HTTP Event Collector (HEC) enables applications and services to send data directly to Splunk via HTTPS. It's the preferred method for cloud-native applications, serverless functions, containers, and any source that can make HTTP requests. HEC is native to Splunk Cloud and requires no additional infrastructure.

Architecture Pattern

Source Application → HTTPS POST → Splunk Cloud HEC Endpoint → Indexers. No forwarders required. Each HEC token controls index, sourcetype, and access permissions.

Prerequisites

HEC Token Configuration

Token Best Practices

One Token Per Source

Create dedicated HEC tokens per application/source. This enables granular access control, easier troubleshooting, and token rotation without affecting other sources.

Token Settings

Setting Recommendation Notes
Name Descriptive: hec_<app>_<env> e.g., hec_webapp_prod
Source Type Set default if source doesn't specify Can override per-event
Index Restrict to allowed indexes Limit blast radius
Acknowledgment Enable for critical sources Confirms delivery
Allow Query String Auth Disable unless required Token in URL is less secure

Create Token via UI

  1. Settings → Data Inputs → HTTP Event Collector
  2. Click "New Token"
  3. Configure name, sourcetype, and allowed indexes
  4. Copy token value immediately (shown only once)
  5. Store token in secrets manager

Python Example

python 
import requests
import json
import time

HEC_URL = "https://inputs.your-stack.splunkcloud.com:443/services/collector/event"
HEC_TOKEN = "YOUR-HEC-TOKEN"  # Store in secrets manager!

def send_to_splunk(event_data, sourcetype="app:custom", index="application"):
    """Send event to Splunk HEC"""
    headers = {
        "Authorization": f"Splunk {HEC_TOKEN}",
        "Content-Type": "application/json"
    }
    
    payload = {
        "event": event_data,
        "sourcetype": sourcetype,
        "index": index,
        "time": time.time()
    }
    
    response = requests.post(
        HEC_URL,
        headers=headers,
        data=json.dumps(payload),
        verify=True  # Enable SSL verification in production
    )
    
    if response.status_code != 200:
        raise Exception(f"HEC Error: {response.status_code} - {response.text}")
    
    return response.json()

# Usage
event = {
    "action": "file_download",
    "user": "jsmith",
    "filename": "sensitive_report.pdf",
    "src_ip": "10.0.1.50"
}

send_to_splunk(event, sourcetype="app:fileaccess", index="application")

AWS Lambda Example

python 
import json
import urllib3
import os

# Get token from environment variable (set via Secrets Manager)
HEC_TOKEN = os.environ['SPLUNK_HEC_TOKEN']
HEC_URL = os.environ['SPLUNK_HEC_URL']

http = urllib3.PoolManager()

def lambda_handler(event, context):
    """Forward CloudWatch Logs to Splunk"""
    
    # Decode CloudWatch Logs event
    import base64
    import gzip
    
    payload = base64.b64decode(event['awslogs']['data'])
    log_data = json.loads(gzip.decompress(payload))
    
    # Build HEC events
    hec_events = []
    for log_event in log_data['logEvents']:
        hec_event = {
            "event": log_event['message'],
            "sourcetype": "aws:cloudwatch:logs",
            "index": "aws",
            "source": log_data['logGroup'],
            "host": log_data['logStream'],
            "time": log_event['timestamp'] / 1000  # Convert ms to seconds
        }
        hec_events.append(json.dumps(hec_event))
    
    # Send to HEC
    response = http.request(
        'POST',
        HEC_URL,
        body='\n'.join(hec_events),
        headers={
            'Authorization': f'Splunk {HEC_TOKEN}',
            'Content-Type': 'application/json'
        }
    )
    
    return {
        'statusCode': response.status,
        'body': response.data.decode('utf-8')
    }

HEC Event Format

Event Fields Reference

Field Required Description
event Yes Event data (string or JSON object)
time No Epoch timestamp (defaults to receipt time)
host No Hostname (defaults to sending IP)
source No Source identifier
sourcetype No Sourcetype (defaults to token setting)
index No Target index (must be allowed by token)
fields No Custom indexed fields (key-value pairs)

Structured vs Unstructured Events

JSON - Structured (Recommended) 
{
  "event": {
    "action": "login",
    "user": "jsmith",
    "src_ip": "10.0.1.50",
    "result": "success"
  },
  "sourcetype": "app:auth",
  "index": "application"
}
JSON - Unstructured (Raw String) 
{
  "event": "2024-02-29 10:30:00 INFO [webapp] User jsmith logged in from 10.0.1.50",
  "sourcetype": "app:log",
  "index": "application"
}

Troubleshooting

  1. Verify token value is correct (no trailing spaces)
  2. Check Authorization header format: Splunk <token>
  3. Ensure token is enabled in Splunk Cloud
  4. Verify token hasn't been rotated
  1. Validate JSON syntax (use jq . to check)
  2. Ensure event field is present
  3. Check for invalid characters in event data
  4. Verify Content-Type header is application/json
  1. Verify token has access to target index
  2. Check token's "Allowed Indexes" setting
  3. Ensure index exists in Splunk Cloud
  4. Remove index field to use token's default
  1. Check index - search with index=* first
  2. Verify sourcetype assignment
  3. Check timestamp extraction (future dates won't appear)
  4. Look for parsing errors in _internal
  1. Implement batching (multiple events per request)
  2. Enable HTTP keep-alive connections
  3. Check for network issues between source and Splunk Cloud
  4. Consider enabling indexer acknowledgment for reliability
  5. Monitor HEC queue size in Splunk Cloud

Security Considerations

Token Security

HEC tokens are API keys. Treat them as secrets: never commit to source control, rotate periodically, and store in secrets managers (AWS Secrets Manager, Azure Key Vault, HashiCorp Vault).

Security Best Practices

  • Token Rotation: Rotate tokens quarterly or after any suspected compromise
  • Least Privilege: Restrict tokens to specific indexes
  • Network Security: Use IP allowlisting where possible
  • Monitoring: Alert on unusual HEC activity patterns
  • Disable Unused: Disable or delete tokens no longer in use

Acceptance Criteria

Phase 1 Gate Requirements

Rollback & Safety

Emergency: Disable HEC Token

Emergency Procedure 
SCENARIO: HEC token compromised, causing volume spike, or source misbehaving

OPTION 1: Disable Token (Immediate - Preferred)
───────────────────────────────────────────────
Splunk Cloud:
1. Settings → Data Inputs → HTTP Event Collector
2. Find token by name
3. Click token → Edit → Enabled = No → Save
4. Effect: Immediate (source receives 403 Forbidden)

On-Prem Splunk:
1. Settings → Data Inputs → HTTP Event Collector
2. Disable token
3. Alternatively: Edit inputs.conf [http://token_name] disabled = 1

OPTION 2: Rotate Token (If Compromise Suspected)
────────────────────────────────────────────────
1. Create NEW token with same settings
2. Update source application with new token
3. Verify data flowing with new token
4. DELETE old token (not just disable)

OPTION 3: Block Source IP (If Known Attacker)
─────────────────────────────────────────────
Configure IP allowlist on HEC token:
1. Edit token → Allowed Hosts
2. Remove offending IP or restrict to known-good IPs

COMMUNICATION:
- If legitimate source disabled, notify application owner
- If compromise suspected, notify Security team
- Document incident for post-mortem

Token Rotation Procedure (Zero Downtime)

Safe Token Rotation 
SCHEDULED TOKEN ROTATION (Quarterly Best Practice)

STEP 1: Create New Token
────────────────────────
1. Settings → Data Inputs → HTTP Event Collector → New Token
2. Use same settings as existing token (index, sourcetype, etc.)
3. Name: [original_name]_v2 (or append date)
4. Save and note new token value

STEP 2: Update Source Application
─────────────────────────────────
1. Update secrets manager with new token
2. Deploy configuration change to application
3. Application restarts with new token

STEP 3: Verify New Token Working
────────────────────────────────
index=_internal sourcetype=splunkd component=HttpInputDataHandler
| search token_name="*v2*" status=200
| stats count
`comment("Should show events arriving via new token")`

STEP 4: Monitor Parallel Operation
──────────────────────────────────
Run both tokens for 24-48 hours to ensure all instances updated

STEP 5: Disable Old Token
─────────────────────────
1. Verify NO traffic on old token:
   index=_internal component=HttpInputDataHandler token_name="old_token" earliest=-24h | stats count
2. If count = 0, disable old token
3. Delete old token after 7 days (grace period)

ROLLBACK: If issues with new token, re-enable old token immediately

HEC Volume Spike Response

Emergency: Unexpected Volume 
SCENARIO: HEC source suddenly sending 10x+ normal volume

STEP 1: Identify Source
───────────────────────
index=_internal sourcetype=splunkd component=HttpInputDataHandler
| stats count by token_name, source_ip
| sort - count
| head 10

STEP 2: Assess Impact
─────────────────────
# Check license impact
index=_internal source=*license_usage.log type=RolloverSummary
| stats sum(b) AS bytes by pool
| eval GB = round(bytes/1024/1024/1024, 2)

STEP 3: Decide Action
─────────────────────
IF LEGITIMATE (new feature, business event):
- Coordinate with source team
- May need license increase
- Consider filtering low-value events

IF ILLEGITIMATE (bug, loop, attack):
- Disable token immediately
- Contact source owner
- Do not re-enable until root cause fixed

IF UNSURE:
- Disable token (err on side of caution)
- Investigate before re-enabling
