Akamai WAF Onboarding

📋 Page Status: HARDENED — Production Onboarding

Last Audit: 2024-02 | Auditor: Detection Engineering Team

Purpose: Complete onboarding procedure for Akamai WAF data into Splunk ES, including architecture selection, ingestion method comparison, field validation, and failure handling. This page eliminates the most common source of confusion in WAF onboarding: conflating "HEC," "API polling," and "installing an add-on" as if they are the same thing.

Ownership: Detection Engineering (requirements, validation) + Platform Engineering (index creation, HEC, network) + Web/Network Operations (Akamai side)

Source Overview

🛡️ What Akamai WAF Is

Akamai Web Application Firewall (WAF / Kona Site Defender / App & API Protector) provides security event logs including blocked attacks, rate limiting events, bot detections, and DDoS mitigation activities. These logs must reach Splunk so ES correlation searches can detect attack patterns, credential stuffing campaigns, and DDoS indicators.

VendorAkamai Technologies
Log TypeSecurity Events (JSON via SIEM Integration or API)
Delivery MethodsSIEM Integration (vendor push to HEC), API Polling (Splunk pulls from Akamai API), or third-party connector
Splunk TASplunk Add-on for Akamai (Splunkbase ID: 4186) — provides modular input AND field extractions
CIM Data ModelsWeb, Intrusion Detection
Typical Volume10-500 GB/day depending on traffic and event verbosity
Typical Latency<2 min (SIEM Integration push) or 5-15 min (API polling)

Why Akamai WAF Onboarding Matters

For organizations with web-facing applications, the WAF sits in front of critical assets and sees every attack attempt before it reaches your infrastructure. Without these logs in Splunk:

GapImpact
Blind to blocked attacksWAF is blocking SQL injection and credential stuffing right now — without visibility you can't understand attack patterns, escalate persistent threats, or correlate with other data sources.
No early warning for DDoSAkamai sees volumetric attacks before they impact origin. Without this data, you only find out when customers complain.
Missing correlation chainA successful account takeover often follows hundreds of blocked credential stuffing attempts. Without WAF logs, you only see the successful login — missing the full kill chain.
Compliance gapsPCI DSS requires logging and monitoring of all access to cardholder data environments. WAF logs are part of this evidence.

HEC vs API Polling vs Add-on — What They Actually Mean

🚨 The #1 Misconception in WAF Onboarding

"I installed the Akamai Add-on, so HEC is set up." — This is wrong. Installing an add-on does NOT configure data ingestion. The add-on provides field extractions and possibly a modular input. You must SEPARATELY configure how events travel from Akamai to Splunk. These are independent decisions.

Precise Definitions

Term What It Actually Is What It Is NOT Analogy
HEC (HTTP Event Collector) A Splunk-side receiving endpoint that accepts JSON or raw data over HTTPS. It listens on a port (default 8088, or 443 for Splunk Cloud) and writes whatever it receives to an index. HEC does not collect data — it waits for data to arrive. A collection mechanism. HEC does not go out and get data. Something else must POST data to HEC. HEC is the mailbox. Something else must deliver the mail.
API Polling A collection mechanism where a process (Splunk modular input, external script, or third-party connector) periodically calls Akamai's SIEM API, retrieves events, and forwards them somewhere (usually to HEC, or directly to an index). A Splunk feature by itself. API polling requires a collector host to run the polling process. API polling is the mail carrier who walks to Akamai, picks up events, and delivers them to the HEC mailbox.
Vendor Push (SIEM Integration) The vendor (Akamai) sends events directly to your HEC endpoint. Akamai's infrastructure POSTs JSON payloads to your Splunk HEC URL. No collector host needed. API polling. With push, Akamai does the sending — Splunk just receives. Vendor push is Akamai delivering the mail themselves straight to your mailbox.
Add-on / TA (Technology Add-on) A Splunk app package that may contain any combination of: (A) modular input code that performs API polling, (B) props.conf / transforms.conf for field extraction, (C) sourcetype definitions and tags for CIM mapping, (D) eventtypes for data model population. Each TA is different — you must inspect what yours contains. An ingestion method by itself. A TA that only contains field extractions does nothing for getting data into Splunk. A TA that contains a modular input still requires configuration and a host to run on. The add-on is the address label and sorting instructions for the mail. It tells Splunk how to read and file the events — but it doesn't move the events.

Common Misconceptions & Corrections

❌ Misconception ✅ Correction
"I installed the TA, so data should be flowing."The TA alone does not move data. You must ALSO configure transport (Layer 1) and receiving (Layer 2). The TA only handles parsing (Layer 3).
"We're using HEC so we don't need a collector."HEC is a receiver. If Akamai supports native push (SIEM Integration), no collector is needed. If you're using API polling, something must run the polling process and POST results to HEC.
"API polling is the same as installing the add-on."Some TAs include a modular input that performs API polling (the Akamai TA does). But the modular input must be configured, enabled, and running on a suitable host (Heavy Forwarder, not search head in most cases).
"SIEM Integration and API polling are two names for the same thing."They are opposite directions. SIEM Integration = Akamai pushes to you. API polling = you pull from Akamai. They produce similar data but have different architecture, latency, failure modes, and configuration steps.
"We configured the connector on the search head."API polling modular inputs should run on a Heavy Forwarder, not the search head. Search heads should not run data collection — it competes with search resources and creates single-point-of-failure risk.
"HEC token = API token."Completely different credentials. HEC token authenticates Splunk ingestion. API token (client_secret + access_token) authenticates against Akamai's API. You may need both if using API polling to HEC.

What Changes When It's API Polling

If your architecture is Option B (API Polling → HEC), this section covers the exact configuration layers, from the collector to Splunk.

Where the Polling Runs

OptionDescriptionWhen to Use
Splunk Modular Input (TA's built-in input) The TA (e.g., Splunk Add-on for Akamai) includes Python code that runs inside Splunk as a scheduled modular input. It calls the Akamai API, processes results, and writes directly to the index (or to HEC). When the TA provides a working modular input AND you have a Heavy Forwarder to run it on.
External Collector (script, container, or tool) A standalone process (Python script, Docker container, vendor connector like Cribl, or cloud function) calls the Akamai API and POSTs results to Splunk HEC. When the TA doesn't provide a modular input, or the modular input doesn't meet requirements (scale, reliability, features).

Configuration Layers — Collector Side (API Polling)

Config Item What It Controls Typical Value What Breaks If Wrong
Auth Method How the collector authenticates to Akamai's SIEM API Akamai EdgeGrid: client_secret, access_token, client_token, host 401/403 errors. Zero events. Verify credentials have SIEM:READ permission.
Config IDs Which Akamai security configurations to poll events for Comma-separated list of numeric config IDs (e.g., 12345,12346) Missing config IDs = missing coverage. Events from excluded configs are invisible.
Poll Interval How frequently the collector calls the API 60-300 seconds. 300s (5 min) is common for the TA. Too frequent → API rate limits (429). Too infrequent → higher latency and larger response payloads.
Pagination / Offset How the collector retrieves large result sets that span multiple API responses Akamai SIEM API uses an offset cursor returned in each response. The collector must store this and use it in the next request. If the cursor is lost, the collector either skips events (gap) or re-reads events (duplicates).
Checkpointing / Cursor Persistence How the collector remembers where it left off between restarts Checkpoint file on disk (TA modular inputs use $SPLUNK_HOME/var/lib/splunk/modinputs/) If checkpoint file is lost (host rebuild, disk failure), collector restarts from beginning → mass duplicates or gap.
Retries & Backoff How the collector handles transient API failures (timeouts, 5xx, rate limits) Exponential backoff with 3-5 retries. The TA typically handles this internally. No retries → single API hiccup causes data gap. Aggressive retries without backoff → triggers rate limit ban.
Dedup Strategy How the collector avoids sending duplicate events to Splunk Cursor-based dedup (only fetch events after the last cursor position). Some collectors use event ID dedup. No dedup → volume inflation, false alert counts, license waste. Especially after collector restart.

What Changes When It's HEC Push (Vendor SIEM Integration)

If your architecture is Option A (Vendor Push → HEC), Akamai sends events directly to your Splunk HEC endpoint. No collector host is needed. But HEC push has its own requirements.

What HEC Push Requires

RequirementDetailWho Owns It
Vendor capability to POSTAkamai must support SIEM Integration (push) for your product and contract. This is a paid feature. Not all Akamai products include it.Akamai Account Team (contract) + Web Ops (configuration)
Internet-accessible HEC endpointAkamai's infrastructure must reach your HEC URL over HTTPS. For Splunk Cloud, this is typically available. For on-prem, you may need a firewall rule or reverse proxy.Platform Engineering / Network Team

⚠️ Many WAFs Don't Push Full Logs

Some WAF vendors only push alert/summary events, not full request logs. Akamai's SIEM Integration sends security events (attacks, rate limits, bot detections) but typically NOT all clean traffic. Verify with your Akamai account team exactly which event types are included in the push. If you need full access logs, you may need a separate data stream (e.g., Akamai DataStream).

Add-on / TA Clarity — What It Gives You, What It Doesn't

⚠️ An Add-on Is NOT an Ingestion Method By Itself

Installing the Splunk Add-on for Akamai does not mean data is flowing. The add-on is a package of configuration files and possibly code. You must understand what YOUR specific TA version contains and configure each component appropriately.

What the Add-on MAY Contain

Component What It Does Where It Matters Present in Akamai TA?
A) Modular Input Python code that performs API polling from inside Splunk. Creates an input stanza in inputs.conf. Heavy Forwarder (where the input runs) ✅ Yes — the Akamai TA includes a SIEM API modular input. But it must be configured and enabled.
B) Field Extractions (props/transforms) Regular expressions, JSON paths, field aliases, and calculated fields that parse raw events into named fields. Search Heads + Indexers (where parsing happens) ✅ Yes — the TA includes props.conf with JSON extraction, field aliases, and CIM mappings.
C) Sourcetype Definitions Defines sourcetypes (e.g., akamai:siem) with timestamp format, line breaking rules, etc. Indexers (for index-time parsing) ✅ Yes — defines akamai:siem and related sourcetypes.
D) CIM Mapping (eventtypes + tags) Eventtypes and tags that make events visible to ES data models (Web, Intrusion Detection). Search Heads (where data model queries run) Verify — check eventtypes.conf and tags.conf in the TA. Coverage varies by TA version.

Prerequisites

🚨 STOP — Verify Contract Before Starting

SIEM Integration is a paid Akamai feature. Many Akamai contracts do NOT include it. Before doing ANY work:

  1. Contact your Akamai account team or check your contract
  2. Confirm "SIEM Integration" or "Security Event Reporting" is included
  3. If not included, adding it can take 2-4 weeks and requires budget approval

If SIEM Integration is not available, you can still use Option B (API Polling) — but you need API credentials and a collector host.

Volume Estimation Before Enabling

⚠️ License Impact Warning

Akamai WAF can generate 10-500+ GB/day. ALWAYS estimate volume before enabling.

Volume Estimation Guide 
Method 1: Akamai Reporting (Preferred)
1. Control Center → Security → Security Reports → last 30 days
2. Total security events / 30 = daily events
3. ~2KB per event average
4. Daily volume = (daily events × 2KB) / 1,000,000 = GB/day

Method 2: Start with Sampling
1. Enable SIEM Integration / polling for ONE config only
2. Monitor for 24 hours: index=waf_akamai | eval size_kb=len(_raw)/1024 | stats sum(size_kb) AS total_kb
3. Extrapolate to all configs

Failure Modes — Comprehensive Reference

API Polling–Specific Failures

# Failure Symptom Root Cause Diagnosis Resolution
F1 API 429 Rate Limit Modular input errors in _internal. Events arrive in bursts with gaps between. Polling too frequently, or multiple collectors polling the same config IDs. index=_internal sourcetype=splunkd "akamai" "429" Increase poll interval (300s minimum). Verify only ONE collector polls each config. Check Akamai rate limit docs.
F2 Expired API Credentials Zero events. Modular input logs 401/403. API client_secret or access_token has expired or been revoked. index=_internal sourcetype=splunkd "akamai" ("401" OR "403" OR "unauthorized") Generate new credentials in Akamai Identity & Access → API Users. Update TA config. Restart input.
F3 Cursor Reset → Mass Duplicates Event volume suddenly doubles or triples. Same events appear multiple times. Checkpoint file deleted or corrupted (host rebuild, disk issue). Collector restarts from beginning of available data. Check duplicate detection SPL (Check 3 above). Check $SPLUNK_HOME/var/lib/splunk/modinputs/ for checkpoint files. If duplicates already ingested: add dedup in searches. Prevent: backup checkpoint files. Restore from backup if available.
F4 Pagination Bug — Events Skipped Event count in Splunk is lower than Akamai reporting shows. No errors in logs. Collector offset handling has a bug, or API response pagination changed after vendor update. Compare: Akamai Security Reports event count vs index=waf_akamai | stats count for same period. Update TA to latest version. If custom collector, audit offset/cursor logic. Contact Akamai support to verify API changes.
F5 Collector Host Down Events stop arriving at a specific time. No errors in Splunk (because the collector isn't running). Heavy Forwarder crashed, was rebooted, or was decommissioned. index=waf_akamai | timechart span=1h count — look for when events stop. Restore collector host. Verify modular input restarts. Check that checkpoint is intact to avoid re-read duplicates.
F6 Timezone Shift Events appear hours off in Splunk. Correlation with other sources produces wrong results. API returns UTC timestamps but props.conf expects local time, or vice versa. Or collector host has wrong timezone. index=waf_akamai | eval lag = _indextime - _time | stats avg(lag) | where avg(lag) > 3600 Verify TZ setting in props.conf. Akamai typically uses epoch (UTC). Ensure TZ = UTC in props.conf stanza.

HEC Push–Specific Failures

# Failure Symptom Root Cause Diagnosis Resolution
F7 HEC Token Revoked / Disabled Events stop abruptly. Akamai connector shows delivery failures (if you check). Someone disabled or deleted the HEC token during maintenance or rotation. | rest /services/data/inputs/http | search name="akamai*" | table name, disabled Re-enable token. If deleted, create new token and update Akamai connector config.
F8 Payload Too Large Some events arrive, but large batches are rejected. Errors in _internal about payload size. HEC has a default max content length (typically 1 MB). Large Akamai event batches exceed it. index=_internal sourcetype=splunkd component=HttpInputDataHandler "content_length" Increase max_content_length in limits.conf [http_input]. Or configure Akamai to send smaller batches.
F9 TLS Certificate Expired Events stop. Akamai cannot establish HTTPS connection. HEC endpoint's TLS certificate has expired. Akamai rejects the connection. Test: curl -v https://<hec-url>/services/collector/health — check cert validity. Renew certificate. For Splunk Cloud, this is managed by Splunk. For on-prem, update cert and restart.
F10 HEC Endpoint Unreachable Events stop. Akamai retries and eventually drops events. Firewall rule changed, DNS change, network outage, or Splunk maintenance. Test from an external host: curl -k https://<hec-url>/services/collector/health Restore network access. Check firewall rules. Verify DNS resolution.

General / Shared Failures

# Failure Symptom Root Cause Diagnosis Resolution
F11 Sourcetype Mismatch → Parsing Fails Events arrive but all CIM fields are null. Raw data looks fine. Events land as httpevent or wrong sourcetype. TA's props.conf doesn't match. index=waf_akamai | stats count BY sourcetype — check for unexpected sourcetypes. Fix HEC token sourcetype override, or fix collector output sourcetype setting. Ensure it matches what the TA expects.
F12 Unexpected Volume Spike License usage spikes. Index grows rapidly. Events may be legitimate (DDoS) or duplicates. Real attack (DDoS generates millions of WAF events), duplicate ingestion (both push and pull running), or config change enabling verbose logging. index=waf_akamai earliest=-24h | timechart span=1h count | where count > [baseline * 3] If real attack: expected, monitor and document. If duplicates: disable one collection method. If config change: revert or add filtering.
F13 Security Configs Silently Removed From Feed Events arrive but coverage decreases. Some attack types stop appearing. Someone edited the SIEM Integration connector or API polling config and removed a config ID. index=waf_akamai earliest=-7d | spath output=cid path=attackData.configId | timechart dc(cid) AS configs_reporting Compare reporting config IDs to inventory. Re-add any missing configs. Set quarterly review reminder.
F14 Both Push AND Pull Running (Double Ingestion) Event count is exactly double what's expected. Duplicate SPL confirms ~50% duplication. SIEM Integration (push) is active AND the TA modular input (poll) is also enabled for the same configs. Check both: Akamai SIEM connector status AND | rest /services/data/inputs/all_modular_inputs | search "akamai" | table title, disabled Disable one method. Keep push (lower latency) if available. Disable modular input if push is active.

Stop & Escalate Conditions

🛑 STOP and Escalate When:
  • SIEM Integration is not in the contract and API credentials are unavailable. You cannot collect data without at least one of these. Escalate to management for contract amendment or API access.
