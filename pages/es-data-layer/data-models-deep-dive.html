🚨 When | tstats Returns Nothing — Diagnostic Checklist

If | tstats count from datamodel=X returns zero, work through this exact sequence:

  1. Is acceleration on? — | rest /services/datamodel/model | search title="X" | table title, acceleration
  2. Is acceleration current? — Check acceleration.earliest_time and look for acceleration errors in index=_internal sourcetype=scheduler "acceleration"
  3. Does raw data exist? — index=YOUR_INDEX sourcetype=YOUR_ST earliest=-1h | stats count
  4. Are CIM fields populated? — index=YOUR_INDEX sourcetype=YOUR_ST | head 10 | table src, dest, user, action
  5. Are correct tags assigned? — index=YOUR_INDEX sourcetype=YOUR_ST | head 10 | table tag, eventtype

The first check that fails is where your problem is. Fix that layer.

Authentication Data Model

What It Represents

Every login attempt across the environment — successful or failed — from any source: Active Directory (Windows Security logs), VPN concentrators, cloud identity providers (Azure AD, Okta), SSH, web applications, database logins. This is typically the most populated and most critical data model for security detections.

Data Model Structure

Node Description Constraint (Tags) Common Sources
Authentication (root) All authentication events tag=authentication All login sources
Authentication.Successful_Authentication Logins where action=success tag=authentication + action=success EventCode 4624 (Windows), success sign-ins (Azure AD)
Authentication.Failed_Authentication Logins where action=failure tag=authentication + action=failure EventCode 4625 (Windows), failed sign-ins (Azure AD)

Fields ES Actually Queries

Data Model Field CIM Field ES Detections Using It Common Missing From
Authentication.actionactionBrute force, account lockout, MFA failureCustom apps (may use "result" or "outcome" instead)
Authentication.useruserEvery identity-based detectionNetwork devices (may log IP only, not username)
Authentication.srcsrcGeo-impossible travel, credential stuffingO365 (may be in different field like "ClientIP")
Authentication.destdestLateral movement, targeted host detectionCloud auth (may not have a "destination" concept)
Authentication.appappPer-application auth analysis, legacy protocol detectionWindows Security (needs calculated field from LogonType)
Authentication.authentication_methodauthentication_methodMFA fatigue detection, method downgradeMost sources (rarely mapped by default TAs)
Authentication.signaturesignatureEvent classification, EventCode-based detectionsNon-Windows sources (Windows maps via TA)

Validation SPL — Authentication

SPL: Authentication Data Model — Full Population Check 
`comment("SAFE: Read-only query")`
`comment("Checks field population in the Authentication data model")`
`comment("Run this BEFORE enabling any auth-based detection")`

| tstats count AS total,
    dc(Authentication.user) AS unique_users,
    dc(Authentication.src) AS unique_sources,
    dc(Authentication.dest) AS unique_dests
    FROM datamodel=Authentication
    WHERE earliest=-4h latest=now
    BY Authentication.action

| rename Authentication.* AS *
| eval health = case(
    total > 0 AND unique_users > 0 AND unique_sources > 0, "✅ HEALTHY — Fields populated",
    total > 0 AND (unique_users=0 OR unique_sources=0), "🟡 PARTIAL — Some fields null",
    total=0, "❌ EMPTY — No data in model (check tags + acceleration)"
)
| table action, total, unique_users, unique_sources, unique_dests, health
SPL: Authentication — Sourcetype Contribution 
`comment("Shows which sourcetypes feed the Authentication data model")`
`comment("Useful to identify which sources are present vs missing")`

| tstats count FROM datamodel=Authentication
    WHERE earliest=-4h latest=now
    BY sourcetype
| sort - count

Healthy vs Broken — Authentication

State What You See What It Means Action
✅ Healthy tstats returns events with action=success and action=failure. user, src, dest fields populated. Multiple sourcetypes contributing. Data model is working. Detections can be enabled. Proceed to detection enablement lifecycle.
🟡 Partial — action null Events appear in model but action field is null or a single value for all events. TA doesn't properly derive the CIM action field. Cannot distinguish success from failure. Check TA's props.conf for EVAL-action or FIELDALIAS-action. Fix in local/.
🟡 Partial — user null Events appear but user field is null or "N/A". TA doesn't extract the username or maps it to a non-CIM field name. Check raw event for the actual username field. Add alias in local/props.conf.
❌ Empty model tstats returns zero events. But index=windows sourcetype=WinEventLog:Security EventCode=4624 shows data. Events are NOT tagged for the Authentication data model. Tags missing. Check eventtypes.conf and tags.conf in the Windows TA. The authentication tag must be present.
❌ Acceleration off tstats returns zero. Raw search shows data. Tags are present. Data model acceleration is disabled or stale. Check acceleration status. Escalate to Splunk admin.

Network Traffic Data Model

What It Represents

Every network connection observed by firewalls, routers, load balancers, VPC flow logs, IDS/IPS, and proxy devices. This is typically the highest-volume data model and the most impacted by CIM field gaps (because network devices vary enormously in log formats).

Data Model Structure

Node Description Constraint (Tags) Common Sources
All_Traffic (root) All network connection events tag=network AND tag=communicate All firewall, IDS, router, flow logs
All_Traffic.Traffic_Allowed Connections that were permitted + action=allowed Firewall allow logs
All_Traffic.Traffic_Blocked Connections that were denied/dropped + action=blocked Firewall deny/drop logs
🚨 Network Traffic Requires TWO Tags

The Network_Traffic data model constraint requires both tag=network AND tag=communicate. If a sourcetype only has one of these tags, its events will NOT appear in the data model. This is one of the most common reasons for Network_Traffic being empty — the TA assigned network but forgot communicate, or vice versa.

Fields ES Actually Queries

Data Model Field CIM Field ES Detections Using It Common Missing From
All_Traffic.srcsrcEvery network detectionRarely missing (most TAs map this)
All_Traffic.destdestEvery network detectionRarely missing
All_Traffic.dest_portdest_portPort scan, unusual service, C2 beaconingVPC flow logs (may use "dstport"), some custom parsers
All_Traffic.actionactionAllowed vs blocked analysis, firewall effectivenessCustom syslog sources (need EVAL to normalize vendor terms like "permit"/"deny" to "allowed"/"blocked")
All_Traffic.transporttransportProtocol anomaly detectionCloud flow logs (may use "protocol" with numeric values)
All_Traffic.bytes_inbytes_inData exfiltration volumeMany firewalls (field name varies: rcvd_bytes, bytes_received, etc.)
All_Traffic.bytes_outbytes_outData exfiltration volumeSame — vendor field names vary significantly
All_Traffic.appappApplication-layer detectionBasic firewalls (only NGFW does app identification)

Validation SPL — Network Traffic

SPL: Network Traffic Data Model — Full Population Check 
`comment("SAFE: Read-only query")`

| tstats count AS total,
    dc(All_Traffic.src) AS unique_sources,
    dc(All_Traffic.dest) AS unique_dests,
    dc(All_Traffic.dest_port) AS unique_dest_ports
    FROM datamodel=Network_Traffic
    WHERE earliest=-4h latest=now
    BY All_Traffic.action

| rename All_Traffic.* AS *
| eval health = case(
    total > 0 AND unique_sources > 0 AND unique_dests > 0 AND unique_dest_ports > 0, "✅ HEALTHY",
    total > 0 AND (unique_sources=0 OR unique_dests=0), "🟡 PARTIAL — Core fields missing",
    total > 0 AND unique_dest_ports=0, "🟡 PARTIAL — dest_port missing (port-based detections fail)",
    total=0, "❌ EMPTY — Check tags: need BOTH 'network' AND 'communicate'"
)
| table action, total, unique_sources, unique_dests, unique_dest_ports, health

Healthy vs Broken — Network Traffic

State What You See Root Cause Fix
✅ HealthyEvents present with action=allowed + action=blocked. src/dest/dest_port populated.—Proceed to detections.
🟡 action is null or single valueAll events show the same action or action is empty.TA doesn't normalize vendor-specific allow/deny terms to CIM "allowed"/"blocked".Add EVAL-action in local/props.conf to map vendor terms.
🟡 bytes_in / bytes_out nullVolume fields are empty despite firewall reporting bytes.Vendor uses non-CIM field names (bytes_received, rcvd_bytes, etc.).Add field aliases in local/props.conf.
❌ Empty — missing one tagtstats returns 0. Raw search shows data. Events have tag=network but NOT tag=communicate.Incomplete tag configuration in the TA.Add missing tag in local/tags.conf. See Safe Add-on Tuning.
❌ Empty — acceleration offtstats returns 0. Tags present. Raw data present.Data model acceleration disabled.Escalate to Splunk admin to enable acceleration.

Web Data Model

What It Represents

HTTP/HTTPS request activity from web proxies, WAF devices, web server access logs, and load balancers. Critical for detecting web application attacks (SQLi, XSS, path traversal), DDoS, and malicious bot activity.

Data Model Structure

Node Description Constraint (Tags) Common Sources
Web (root)All web request eventstag=webProxy, WAF, IIS, Apache, Nginx, Cloudflare, Akamai
Web.ProxyProxy-mediated requeststag=web + tag=proxySquid, Zscaler, BlueCoat

Fields ES Actually Queries

Data Model Field CIM Field ES Detections Using It Common Missing From
Web.srcsrcAttack source identificationCDN/WAF logs (may use "client_ip" or "true_client_ip")
Web.destdestTarget server identificationProxy logs (may use "host" header value)
Web.urlurlAttack payload detection (SQLi, XSS in URL)WAF logs (field name varies: "uri", "request_uri", "cs-uri-stem")
Web.uri_pathuri_pathPath traversal, restricted path accessMany sources (need extraction from full URL)
Web.statusstatusError rate detection, successful exploit identificationWAF logs (may use "response_code", "sc-status")
Web.http_methodhttp_methodMethod anomaly, PUT/DELETE abuseOlder web server logs
Web.http_user_agenthttp_user_agentBot detection, scanner identificationCDN summary logs (may be truncated or omitted)
Web.bytes_in / Web.bytes_outbytes_in / bytes_outUpload/download volume anomalyVaries widely by source

Validation SPL — Web

SPL: Web Data Model — Full Population Check 
`comment("SAFE: Read-only query")`

| tstats count AS total,
    dc(Web.src) AS unique_sources,
    dc(Web.dest) AS unique_dests,
    dc(Web.url) AS unique_urls,
    dc(Web.status) AS unique_statuses
    FROM datamodel=Web
    WHERE earliest=-4h latest=now
    BY Web.http_method

| rename Web.* AS *
| eval health = case(
    total > 0 AND unique_sources > 0 AND unique_urls > 0 AND unique_statuses > 0, "✅ HEALTHY",
    total > 0 AND unique_urls=0, "🟡 PARTIAL — url field missing (WAF detections fail)",
    total > 0 AND unique_statuses=0, "🟡 PARTIAL — status field missing (exploit success detection fails)",
    total=0, "❌ EMPTY — Check for tag=web"
)
| table http_method, total, unique_sources, unique_dests, unique_urls, unique_statuses, health

Healthy vs Broken — Web

State What You See Root Cause Fix
✅ HealthyEvents with HTTP methods, src/dest/url/status populated, multiple sourcetypes.—Proceed to WAF detections.
🟡 url / uri_path nullEvents present but URL fields empty.WAF/proxy TA maps URL to a non-CIM field name.Add field alias: FIELDALIAS-url = request_uri AS url in local/props.conf.

Endpoint Data Model (High-Level)

What It Represents

Process execution, file system activity, registry changes, and service events on endpoints. This is the primary data model for endpoint threat detection (ransomware, credential dumping, lateral movement, living-off-the-land). It is the most complex data model with many sub-nodes.

Key Sub-Models

Node What It Covers Tags Required Primary Sources
Endpoint.ProcessesProcess creation, command lines, parent-child relationshipstag=process, tag=reportSysmon EventID 1, WinEventLog 4688, EDR process telemetry
Endpoint.FilesystemFile creation, modification, deletiontag=endpoint, tag=filesystemSysmon EventID 11/15/23, EDR file events
Endpoint.RegistryRegistry key/value creation, modification, deletiontag=endpoint, tag=registrySysmon EventID 12/13/14
Endpoint.ServicesService installation and changestag=endpoint, tag=serviceWindows System EventID 7045

Key Fields — Endpoint.Processes (Most Used)

CIM Field Priority What It Is If Missing
process_nameREQUIREDName of the executable (e.g., cmd.exe, powershell.exe)🔴 Cannot match on process names. All LOLBIN detections fail.
processREQUIREDFull command line🔴 Cannot analyze command-line arguments. Most advanced detections fail.
parent_process_nameREQUIREDParent process executable name🔴 Cannot detect suspicious parent-child relationships (Excel→cmd, Word→PowerShell).
destREQUIREDHostname of the endpoint🔴 Cannot identify WHICH endpoint is compromised.
userHIGHUser account running the process🟡 Cannot attribute process to user. Reduces investigation context.
process_idMEDIUMPID⚪ Reduces correlation precision in process tree analysis.

Validation SPL — Endpoint.Processes

SPL: Endpoint Processes — Population Check 
`comment("SAFE: Read-only query")`

| tstats count AS total,
    dc(Processes.process_name) AS unique_process_names,
    dc(Processes.dest) AS unique_endpoints,
    dc(Processes.user) AS unique_users
    FROM datamodel=Endpoint.Processes
    WHERE earliest=-4h latest=now

| eval health = case(
    total > 0 AND unique_process_names > 0 AND unique_endpoints > 0, "✅ HEALTHY",
    total > 0 AND unique_process_names=0, "🟡 PARTIAL — process_name missing",
    total=0, "❌ EMPTY — Check tags: process + report"
)
| table total, unique_process_names, unique_endpoints, unique_users, health

Failure Modes

Failure Symptom Root Cause Impact Fix
Data model returns zero events tstats count=0 for a model that should have data Missing tags OR acceleration off OR acceleration stale All detections for this model silently fail Work through the tstats diagnostic checklist (top of page)
Data model has events but fields null tstats count > 0 but dc(field)=0 Tags present (events visible) but CIM field alias missing Detections that filter on the null field return zero Add field alias in TA local/props.conf
Wrong data in data model Data model contains events from an unrelated sourcetype Tags were too broadly applied (e.g., tag=authentication on non-auth events) Detections fire on irrelevant data. False positives. Narrow the eventtype definition to match only the correct events
Acceleration backlog tstats returns data but only for older time ranges; recent data missing Acceleration is running but hasn't caught up (common after re-enable or after volume spike) Detections with short lookback (15min, 1hr) miss recent events Wait for acceleration to catch up. Monitor | rest /services/admin/summarization
Field value mismatch Detection expects action="allowed" but data has action="permit" CIM EVAL-action mapping uses wrong normalization values Detection filter doesn't match. Appears as "no events" even though data exists. Check CIM spec for expected values. Fix EVAL-action in local/props.conf.

Stop & Escalate Conditions

🛑 STOP and Escalate When:
  • Any data model used by active detections returns zero events. This is a production detection failure. Investigate immediately — check acceleration, then tags, then data source.
  • Data model acceleration shows a backlog of more than 4 hours. Detections with short lookback windows are missing data. Escalate to Splunk admin for resource investigation.
  • A TA upgrade causes a data model to lose events. The upgrade may have changed field aliases or tags. Verify CIM status post-upgrade before accepting the change.
  • Wrong data appears in a data model. Over-tagged events pollute detection results. Narrow the eventtype/tag scope immediately.
  • Multiple data models are empty simultaneously. Likely a systemic issue: CIM add-on problem, search head cluster issue, or global acceleration failure.

Common Anti-Patterns

Anti-Pattern Why It's Dangerous What to Do Instead
"I'll just check one data model and assume the rest are fine"Each model has different tag requirements and different field mapping challenges. Authentication working doesn't mean Network_Traffic works.Validate EACH data model you plan to use for detections. Independently.
"tstats returns some data so we're good""Some data" may be from one sourcetype while another critical sourcetype is completely missing from the model.Check sourcetype contribution per model. Verify all expected sources are present.
"We'll fix the Endpoint model later — auth and network are enough"Endpoint detections catch ransomware, credential dumping, and lateral movement. Deferring endpoint coverage creates a critical gap.Prioritize by threat model. If ransomware is a top risk, Endpoint is not optional.
"The data model has events so field population is fine"Events can appear in a model with many fields null. Count > 0 doesn't mean fields are populated.Always check dc(field) alongside count. A model with 10,000 events and 0 unique users is broken for identity-based detections.
