Phase 1: Log Coverage

Alternate Onboarding Paths

Specialized ingestion methods for cloud integrations, databases, streaming platforms, and custom requirements

📋 Page Status: HARDENED

Last Audit: 2024-02 | Auditor: Detection Engineering Team

Alternate paths include additional complexity and risk factors compared to primary paths.

🚨 CRITICAL: Alternate Paths Require Additional Expertise

Alternate paths introduce components outside Splunk's direct control. Before selecting an alternate path:

  • Confirm primary paths won't work — Document why standard methods are insufficient
  • Identify infrastructure owner — Who manages Event Hubs, Kafka, databases?
  • Plan for failure modes — What happens when the middleware fails?
  • Establish monitoring — How will you detect data gaps?
⚠️ Complexity vs. Benefit Tradeoff

Each alternate path adds operational complexity:

  • Azure Event Hubs: Requires Azure expertise, throughput unit management
  • Kafka Connect: Requires Kafka expertise, connector maintenance, on-prem HF
  • DB Connect: Requires database access, query optimization, on-prem HF
  • Scripted Inputs: Requires custom code maintenance, error handling

Only use alternate paths when the benefit justifies the complexity.

When to Use Alternate Paths

While primary paths (syslog, UF, HEC) cover most scenarios, some data sources require specialized approaches. Use alternate paths when the source doesn't support standard methods, when existing infrastructure provides better integration points, or when specific architectural requirements dictate the approach.

Path Selection

Always evaluate primary paths first. Alternate paths introduce additional components and complexity. Document the rationale for choosing an alternate path in project scope documentation.

Available Alternate Paths

Azure Event Hubs

Stream data from Azure services (Entra ID, Defender, Activity Logs) via Event Hubs to Splunk Cloud using the Azure Add-on.

Architecture Considerations

On-Premises Components

Kafka Connect and DB Connect require on-premises Heavy Forwarders. Factor in infrastructure provisioning, maintenance, and monitoring when selecting these paths.

Reliability Patterns

  • Event Hubs/Kinesis: Cloud-managed, built-in retry and buffering
  • Kafka Connect: Requires connector HA configuration
  • DB Connect: Checkpoint-based, handles HF restart gracefully
  • Scripted Inputs: Must implement checkpointing manually

Volume Considerations

  • Event Hubs: Throughput units determine max ingestion rate
  • Kafka: Partition count affects parallelism
  • DB Connect: Query frequency vs database load tradeoff
  • Scripted: API rate limits may throttle collection
