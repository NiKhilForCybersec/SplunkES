Azure Event Hubs Integration

Stream Azure and Microsoft 365 logs via Event Hubs to Splunk using the Splunk Add-on for Microsoft Cloud Services

📋 Page Status: HARDENED

Last Audit: 2024-02 | Auditor: Detection Engineering Team

This page includes Azure-specific configuration guidance, failure modes, and rollback procedures.

☁️ Splunk Cloud Safety Box — Azure Event Hubs

✅ Allowed in Cloud: Splunk Data Manager natively supports Azure Event Hubs on Victoria Experience. The Splunk Add-on for Microsoft Cloud Services is Cloud-vetted. HEC token creation, index creation, and all validation SPL work in Cloud.

⚠️ Restricted in Cloud: On Classic Experience, the add-on's modular input must run on IDM (not SH). Editing props/transforms on indexers requires a support ticket.

🔄 Cloud-Safe Alternative: Use Data Manager (Victoria) for automated setup. Or install the Cloud-vetted add-on on SH (Victoria) / IDM (Classic). For hybrid, deploy a customer-managed HF to consume from Event Hub and forward to Cloud.

🚨 CRITICAL: Azure Event Hubs Has Multiple Failure Points

Event Hubs ingestion involves Azure infrastructure, Heavy Forwarder, and Splunk. Any component failure causes data gaps. Ensure:

  • Monitor ALL components: Event Hubs metrics, HF health, Splunk input status
  • Azure permissions are NOT service account: Use dedicated app registration with certificate auth
  • Certificate expiry alerts: Certificates expire — set reminders 30 days before
  • Throughput unit planning: Under-provisioned TUs cause data loss
⚠️ Azure Cost Considerations

Event Hubs pricing is based on throughput units and retention:

  • Standard tier: ~$22/month per throughput unit + ingress/egress costs
  • Retention: Default 24 hours; longer retention = higher cost
  • Right-size: Start with 2 TUs, scale based on actual usage

Architecture Overview

Azure Event Hubs provides a scalable, high-throughput data streaming platform ideal for ingesting large volumes of Azure-native logs into Splunk. This method is preferred for Azure Activity Logs, Microsoft 365 audit logs, Azure AD sign-ins, and Defender for Cloud alerts.

Step 1: Create Event Hubs Namespace

Naming Convention

Use consistent naming: evhns-{company}-{environment}-{region} for namespaces and evh-{logtype} for individual hubs.

Azure CLI Commands

Azure CLI 
# Create Resource Group
az group create \
  --name rg-splunk-eventhubs \
  --location canadacentral

# Create Event Hubs Namespace
az eventhubs namespace create \
  --name evhns-company-prod-cc \
  --resource-group rg-splunk-eventhubs \
  --location canadacentral \
  --sku Standard \
  --capacity 2

# Create Event Hubs for each log type
az eventhubs eventhub create \
  --name evh-azuread-signin \
  --namespace-name evhns-company-prod-cc \
  --resource-group rg-splunk-eventhubs \
  --partition-count 4 \
  --message-retention 7

az eventhubs eventhub create \
  --name evh-m365-audit \
  --namespace-name evhns-company-prod-cc \
  --resource-group rg-splunk-eventhubs \
  --partition-count 4 \
  --message-retention 7

az eventhubs eventhub create \
  --name evh-azure-activity \
  --namespace-name evhns-company-prod-cc \
  --resource-group rg-splunk-eventhubs \
  --partition-count 4 \
  --message-retention 7

Step 2: Configure Azure Diagnostic Settings

Azure AD Sign-in Logs

Azure CLI 
# Get Event Hub resource ID
EVENTHUB_ID=$(az eventhubs eventhub show \
  --name evh-azuread-signin \
  --namespace-name evhns-company-prod-cc \
  --resource-group rg-splunk-eventhubs \
  --query id -o tsv)

  --name RootManageSharedAccessKey \
  --namespace-name evhns-company-prod-cc \

Step 3: Create App Registration

Security Best Practice

Use certificate authentication instead of client secrets for production. Certificates provide stronger security and longer validity periods.

Create Service Principal

Azure CLI 
# Create App Registration
az ad app create \
  --display-name "Splunk Event Hubs Reader" \
  --sign-in-audience AzureADMyOrg

# Get the App ID
APP_ID=$(az ad app list --display-name "Splunk Event Hubs Reader" --query "[0].appId" -o tsv)

# Create Service Principal
az ad sp create --id $APP_ID

# Get Service Principal Object ID
SP_OID=$(az ad sp show --id $APP_ID --query id -o tsv)

# Assign Event Hubs Data Receiver role
az role assignment create \
  --assignee $SP_OID \
  --role "Azure Event Hubs Data Receiver" \
  --scope "/subscriptions/{subscription-id}/resourceGroups/rg-splunk-eventhubs"

Generate Certificate (Recommended)

Bash 
# Generate self-signed certificate (2 year validity)
openssl req -x509 -nodes -days 730 \
  -newkey rsa:2048 \
  -keyout splunk-eventhubs.key \
  -out splunk-eventhubs.crt \
  -subj "/CN=Splunk Event Hubs Reader"

# Create PEM file for Splunk
cat splunk-eventhubs.key splunk-eventhubs.crt > splunk-eventhubs.pem

# Upload certificate to Azure AD app
az ad app credential reset \
  --id $APP_ID \
  --cert @splunk-eventhubs.crt \
  --append

Troubleshooting

No Data Arriving in Splunk
  1. Verify Event Hub has data: Azure Portal → Event Hubs → Metrics → Incoming Messages
  2. Check modular input logs: 
    index=_internal sourcetype=splunkd (ERROR OR WARN) 
    "azure_event_hub" OR "Splunk_TA_microsoft"
| table _time, log_level, message
  3. Verify network connectivity: 
    # From Heavy Forwarder
curl -v https://evhns-company-prod-cc.servicebus.windows.net/
  4. Check certificate permissions: 
    ls -la $SPLUNK_HOME/etc/apps/Splunk_TA_microsoft-cloudservices/certs/
Authentication Errors
  • Verify Tenant ID and Client ID match Azure AD app registration
  • Confirm certificate is uploaded to Azure AD app and not expired
  • Check Service Principal has "Azure Event Hubs Data Receiver" role
  • Ensure PEM file contains both private key and certificate
High Latency / Lag
  • Increase max_batch_size in inputs.conf (up to 5000)
  • Add more partitions to Event Hub (requires namespace tier upgrade)
  • Scale Heavy Forwarder CPU/memory
  • Check for checkpoint lag: 
    index=_internal sourcetype=splunkd "checkpoint" "azure_event_hub"
| stats latest(_time) BY data_input

Rollback & Safety

Emergency: Disable Event Hub Ingestion

Emergency Procedure 
SCENARIO: Event Hub ingestion causing issues (volume spike, parsing errors, HF overload)

OPTION 1: Disable Splunk Input (Preferred)
─────────────────────────────────────────
1. SSH to Heavy Forwarder
2. Edit: $SPLUNK_HOME/etc/apps/Splunk_TA_microsoft-cloudservices/local/inputs.conf
3. Add: disabled = 1 to the problematic input stanza
4. Restart: $SPLUNK_HOME/bin/splunk restart

OPTION 2: Disable via Splunk Web
────────────────────────────────
1. Settings → Data Inputs → Azure Event Hub
2. Find input → Edit → Disabled = Yes
3. Save

OPTION 3: Block at Azure Side (If HF Overwhelmed)
─────────────────────────────────────────────────
1. Azure Portal → Event Hubs Namespace → Access Control (IAM)
2. Remove "Azure Event Hubs Data Receiver" role from Service Principal
3. This immediately stops Splunk from reading
4. Data continues to queue in Event Hub (up to retention limit)

COMMUNICATION:
- Notify SOC (Azure log gap occurring)
- Notify Azure team if Azure-side changes made
- Document start/end time for audit

Certificate Renewal Procedure

Zero-Downtime Certificate Rotation 
SCENARIO: Certificate approaching expiry (30+ days notice)

STEP 1: Generate New Certificate
────────────────────────────────
openssl req -x509 -newkey rsa:2048 -keyout new_key.pem -out new_cert.pem -days 730 -nodes

STEP 2: Upload to Azure AD App Registration
───────────────────────────────────────────
1. Azure Portal → App registrations → Your App
2. Certificates & secrets → Upload certificate
3. Upload new_cert.pem (keep old cert active)

STEP 3: Create Combined PEM for Splunk
──────────────────────────────────────
cat new_key.pem new_cert.pem > combined_new.pem

STEP 4: Update Splunk Configuration
───────────────────────────────────
1. Copy combined_new.pem to HF: $SPLUNK_HOME/etc/apps/Splunk_TA_microsoft-cloudservices/certs/
2. Update inputs.conf with new certificate path
3. Restart Splunk: $SPLUNK_HOME/bin/splunk restart

STEP 5: Verify New Certificate Working
──────────────────────────────────────
index=_internal sourcetype=splunkd "azure_event_hub" earliest=-15m
| stats count BY log_level
# Should show INFO only, no ERROR

STEP 6: Remove Old Certificate
──────────────────────────────
1. Wait 24 hours to confirm new cert working
2. Azure Portal → App registrations → Your App
3. Certificates & secrets → Delete old certificate

SCHEDULE: Set calendar reminder 60 days before new cert expires

Event Hub Health Monitoring Query

SPL: Monitor Event Hub Input Health 
`comment("Create scheduled alert to detect Event Hub failures")`

index=_internal sourcetype=splunkd component=ModularInputs 
    (azure_event_hub OR "Splunk_TA_microsoft-cloudservices") earliest=-1h
| stats 
    latest(_time) AS last_event,
    sum(eval(if(log_level="ERROR", 1, 0))) AS error_count,
    sum(eval(if(log_level="WARN", 1, 0))) AS warn_count
    BY data_input
| eval hours_since = round((now() - last_event)/3600, 1)
| eval status = case(
    error_count > 0, "🔴 ERRORS - Check immediately",
    hours_since > 1, "🟠 STALE - No activity >1h",
    warn_count > 5, "🟡 WARNINGS - Review logs",
    true(), "✅ Healthy"
)
| table data_input, status, last_event, error_count, warn_count

`comment("Alert when status contains 🔴 or 🟠")`
